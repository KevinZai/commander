## What is a dynamic workflow?

A dynamic workflow is a JavaScript script that Claude Code's Workflow tool runs in the background. Unlike a skill (which runs inline) or a single subagent, a workflow:

- Runs **in the background** without blocking your session
- **Spawns many agents concurrently**, each on its own slice or dimension
- Has a **fresh agent try to refute** each finding before it is reported
- Returns one synthesized result

Plugins can ship workflows. Each plugin workflow runs from the prompt as `/<plugin>:<name>`, so Commander's run as **`/commander:<name>`**. List everything available with `/workflows`.

## The six plugin workflows

All six live in `commander/cowork-plugin/workflows/`:

| Workflow | Run it | Also behind | What it does |
|---|---|---|---|
| `ccc-audit` | `/commander:ccc-audit` | `/ccc-xray` | Repo health audit — one finder per dimension, every finding adversarially verified, scored scorecard |
| `ccc-deep-review` | `/commander:ccc-deep-review` | `/ccc-review` | Branch review over four weighted dimensions, every finding verified, severity-grouped verdict |
| `ccc-migrate` | `/commander:ccc-migrate` | `/ccc-ultracode` | Discover every matching site, transform each in its own worktree, verify each change with an independent skeptic. Pipeline by default |
| `ccc-fleet` | `/commander:ccc-fleet` | `/ccc-fleet` | Fan-out slices with independent verifiers, sequential stage chains, a judge panel or a multi-lens debate |
| `ccc-prompt-audit` | `/commander:ccc-prompt-audit` | `/ccc-more` | **New in v8.** Checks every plugin `SKILL.md` and agent file against the prompt standard; read-only |
| `ccc-release-audit` | `/commander:ccc-release-audit` | `/ccc-more` | **New in v8.** Runs every release gate and returns go or no-go with blockers |

You don't need to know the scripts to use them: run the skill, or type the `/commander:<name>` command. `/ccc-ultracode` picks the right one from a chip picker.

## Writing your own workflow

A workflow file exports a pure-literal `meta` object and uses the Workflow script API (`agent()`, `parallel()`, `pipeline()`, `phase()`, `log()`, `args`):

```javascript
// workflows/my-review.workflow.js
export const meta = {
  name: 'my-review',
  description: 'Review one file for security and performance, then verify each finding.',
}

const file = (args && args.file) || 'src/index.ts'

const [security, perf] = await parallel([
  () => agent(`Review ${file} for security issues. Return findings with path:line evidence.`),
  () => agent(`Profile ${file} for performance hot paths. Return findings with path:line evidence.`),
])

const verified = await agent(
  `Try to refute each finding below by reading the code. Keep only confirmed ones.\n${security}\n${perf}`
)
log(verified)
```

A plugin picks up files in its `workflows/` directory automatically. Two platform rules worth knowing: `meta` must be a pure literal, and `Date.now()` and `Math.random()` throw inside a workflow. `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` pins the model for every agent a workflow spawns.

## The `/deep-research` built-in

Claude Code ships `/deep-research` as a built-in workflow — fan-out search, fact-checking and a cited report. `/ccc-research` and `/ccc-ultracode` hand research questions to it.

## Requirements

Plugin workflows need a Claude Code build with the Workflow tool. Check with `claude --version` and update with `claude update`. Run `/workflows` to see the six Commander workflows once the plugin is installed.
