CC Commander registers **30 lifecycle hook events** with **52 total handlers** that fire automatically around every Claude Code session. All hooks are free — no tier gating, no feature flags.

<Note>
  **v8.0.0 wired seven new events** — `PermissionDenied`, `PreModelSwitch`, `PostModelSwitch`, `TeammateIdle`, `CwdChanged`, `DirectoryAdded` and `FileChanged` — taking the registry from 23 to 30 events. Existing handlers are unchanged. See [Hooks 2026](/hooks-2026) for the full per-handler registry.
</Note>

Every command uses a quoted `"${CLAUDE_PLUGIN_ROOT}"` for portable path resolution (Desktop installs live under a path with a space). Telemetry handlers fail open — if one errors, the session continues uninterrupted.

## Hook registry (core events)

The most important events, for quick reference. **See [Hooks 2026](/hooks-2026) for all 30 events and 52 handlers.**

| Event | Handlers | Scripts | Purpose |
|-------|----------|---------|---------|
| `SessionStart` | 5 | `session-start-orchestrator.js` (one process for session-start, the stale-CLAUDE.md nudge, post-compact recovery and the Fable-armed nudge), `license-check.js`, `git-truth.js`, `update-nudge.js`, `console-autopen.js` | Seed state, watch `CLAUDE.md` for changes, restore post-compact context, update nudge |
| `UserPromptSubmit` | 6 | `suggest-ticker.js`, `intent-classifier.js`, `context-warning.js`, `context-guard.js`, `user-prompt-submit.js`, `skill-runs-logger.js` | Ambient suggestion tick, skill routing, context warnings, skill-run telemetry |
| `PreToolUse` | 6 | `cost-tracker.js`, `cost-ceiling-enforcer.js`, `secret-leak-guard.js`, `config-protection.js`, `doc-file-warning.js`, `git-push-reminder.js` | Tool-call budget, ceiling, leaked-secret scan, config protection, pre-push reminder |
| `PostToolUse` | 4 | `knowledge-capture.js`, `mission-control-feed.js`, `console-log-warn.js`, `pr-link-notify.js` | Knowledge capture, Mission Control feed, `console.log` warning, PR links |
| `PermissionDenied` | 1 | `permission-denied-logger.js` | Auto-mode denials reach `/ccc-safety` |
| `Stop` | 3 | `suggest-lightweight.js`, `clickability-watch.js`, `intent-classifier.js` | End-of-turn suggestion, clickability telemetry, and the "what next" menu after a skill ran |
| `SessionEnd` | 2 | `session-save.js`, `session-end.js` | Save the session and its summary |
| `SubagentStop` | 2 | `subagent-stop.js`, `agent-run-logger.js` | Subagent cost roll-up and agent-run log |

`WorktreeCreate` and `WorktreeRemove` are deliberately not registered: a hook there replaces git's own worktree handling. The Codex mirror carries the handlers for the 12 events Codex supports.

## State Layout

All hook state lives in `~/.claude/commander/` (CCC's own namespace — never touches other `.claude/` contents):

```
~/.claude/commander/
├── sessions/
│   ├── active-session.json       # current session metadata (created on SessionStart)
│   ├── active-cost.json          # incremented on each PreToolUse
│   └── YYYY-MM-DD-{hash}.json    # archived on Stop
├── knowledge/
│   ├── auto-captures.jsonl       # tail of Write/Edit events
│   └── {timestamp}.json          # manual lessons via /ccc-knowledge
├── fleet/
│   └── notifications.jsonl       # fleet agent completion log
├── pre-compact/
│   └── YYYY-MM-DD-{hash}.json    # state saved before compaction
└── config.json                   # user settings (theme, name, etc.)
```

<Note>
  **Privacy:** Hook state (config, session data, fleet logs) is stored locally at `~/.claude/commander/`. Hooks do send anonymous usage telemetry (event name, hook name, OS, plugin version) unless you opt out with `CCC_TELEMETRY=0` or `~/.commander/config.json → {"telemetry": false}`. No prompts, file contents, or paths are ever transmitted.
</Note>

## Disabling Individual Hooks

To disable a single hook without uninstalling the plugin, add to `~/.claude/commander/config.json`:

```json
{
  "hooks": {
    "UserPromptSubmit": false,
    "Notification": false
  }
}
```

The hook wrapper checks this flag before running each handler. Disabling a hook event disables all its handlers.

## Hook Execution Model

Hooks are JavaScript files executed natively by Claude Code's hook runtime. They:

1. Receive the event context as JSON on stdin
2. Run their logic (typically 10-50ms)
3. Print nothing, or JSON with the fields that event accepts (for example `permissionDecision` on `PreToolUse`)

Only the guards on `PreToolUse` and `PermissionRequest` can deny a tool call. Everything else is informational. This is by design: hooks should enhance, never gate.

See [Architecture](/architecture) for how hooks fit into the full data flow. See [Hooks 2026](/hooks-2026) for the complete registry of all 30 events and 52 handlers.
