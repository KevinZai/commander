## Brain / Hands

CC Commander follows a **brain/hands** separation pattern built on Anthropic's Claude Agent SDK:

- **Brain (Claude):** The main Claude Code session reads project context, routes intent, and makes decisions
- **Hands (CC Commander):** Skills, hooks, and sub-agent personas execute the work — scoped, specialized, and disposable

When you invoke `/ccc-review`, Claude isn't guessing how to do a code review. It loads the `reviewer` persona (`opus` alias, read-only tools, structured severity format) and delegates. When it finishes, the persona is gone. The next task starts fresh.

This keeps context clean, prevents drift, and means each specialist operates at full capacity instead of a generalist stretched thin.

## Built on the Claude Agent SDK

CC Commander's sub-agent architecture follows the same pattern Anthropic describes in their [Claude Agent SDK](https://code.claude.com/docs/en/sub-agents). Each plugin skill is a lightweight orchestration layer that:

1. Reads project state (git diff, file structure, active tasks)
2. Selects the right specialist persona
3. Delegates with a scoped tool allowlist, model alias and effort level
4. Returns structured output to the main session

The plugin itself requires no external server, no API key, and no network call. It runs fully offline via the plugin manifest — the Claude Agent SDK pattern is implemented as skill files and hook scripts that Claude Code executes natively.

## 22 Specialist Sub-Agent Personas

Each agent declares a model **alias** and an effort level in its frontmatter, so it tracks the newest model in its line. Skills invoke them automatically; browse them with `/ccc-browse`.

| Tier | Agents |
|---|---|
| `fable` (Fable 5.1), effort `xhigh` | `architect`, `security-auditor` |
| `opus` (Opus 5.5), effort `high` | `builder`, `reviewer`, `debugger`, `designer`, `qa-engineer`, `devops-engineer`, `data-analyst`, `product-manager`, `performance-engineer`, `researcher`, and the `typescript`, `python`, `go`, `rust`, `java`, `kotlin` and `csharp` reviewers |
| `sonnet` (Sonnet 5.5), effort `medium` | `technical-writer`, `content-strategist`, `fleet-worker` |

Read-only reviewers use `disallowedTools` so they cannot edit. Fable is reserved for work where a wrong call is expensive: architecture, threat models, and verification of load-bearing claims. See [Agents](/plugin/agents) for each persona.

## 30 Lifecycle Hooks / 52 Handlers

Hooks fire automatically around Claude Code sessions; each event can have several handlers. The main groups:

| Group | Events |
|---|---|
| Session | `SessionStart`, `Setup`, `SessionEnd`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged` |
| Prompt | `UserPromptSubmit`, `UserPromptExpansion` |
| Tools and permissions | `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `PermissionRequest`, `PermissionDenied` |
| Model | `PreModelSwitch`, `PostModelSwitch` |
| Agents and tasks | `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `TeammateIdle` |
| Turn and context | `Stop`, `StopFailure`, `Notification`, `PreCompact`, `PostCompact`, `Elicitation`, `ElicitationResult` |

Telemetry handlers fail open — if one errors, the session continues. Hook state lives in `~/.claude/commander/` and never touches other `.claude/` contents. `WorktreeCreate` and `WorktreeRemove` are deliberately not registered, because a hook there replaces git's own worktree handling. See [Hooks 2026](/hooks-2026) for the per-handler registry.

## Plugin workflows

Skills that need many agents use the second execution path: **dynamic workflows**. A workflow is a script the Workflow tool runs in the background, spawning agents concurrently and having fresh agents refute each finding before it is reported.

Commander ships six, each runnable as `/commander:<name>`:

| Workflow | Used by |
|----------|---------|
| `ccc-audit` | `/ccc-xray` |
| `ccc-deep-review` | `/ccc-review` |
| `ccc-migrate` | `/ccc-ultracode` migrations |
| `ccc-fleet` | `/ccc-fleet` |
| `ccc-prompt-audit` | `/ccc-more` |
| `ccc-release-audit` | `/ccc-more` |

See [Dynamic Workflows](/dynamic-workflows) for the developer reference.

## The Commander HUD mod

On Claude Code 2.1.287+ (Desktop 2.1.286+), the plugin's mod draws a band above the prompt with the Fable Method state, running agents, the session's tool-call budget and an update pill; `/ccc-hud` toggles it without a model turn. It is observe-only: no tool approval, no model calls, no network, and it reads only `~/.claude/commander/`. Elsewhere Commander runs hooks-only.

## Data Flow

**Standard (Agent dispatch):**

```
User prompt
    ↓
SessionStart hook (context loaded)
    ↓
UserPromptSubmit hook (intent classified → skill suggested)
    ↓
Skill invoked (e.g. /ccc-review)
    ↓
Skill reads project state + selects persona
    ↓
Sub-agent spawned with scoped tools + turn budget
    ↓
Sub-agent executes → structured output returned
    ↓
PostToolUse hook (knowledge captured)
    ↓
Main session resumes with result
    ↓
SessionEnd hook (session saved)
```

**Workflow path:**

```
Skill invoked (e.g. /ccc-xray)
    ↓
TaskCreated hook fires
    ↓
Workflow script launched in background
    ↓
N agents spawn in parallel (one per dimension or slice)
    ↓
A fresh agent tries to refute each finding
    ↓
TaskCompleted hook fires
    ↓
Structured result returned to main session
```

## Offline-First

The entire plugin works without any network connection. Skills, personas, and hooks are plain markdown + JavaScript files executed natively by Claude Code. The bundled `.mcp.json` adds 2 credential-free servers (`context7`, `sequential-thinking`); 16 more external integrations (Linear, GitHub, Slack, etc.) connect separately, opt-in via `/ccc-connect` — none of them are required, the plugin is fully functional without any of them.

See [vs aider.chat](/compare/vs-aider) for a direct positioning comparison.
