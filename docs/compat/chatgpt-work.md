> Status: **verified against live docs on 2026-07-10** (ChatGPT Work launched 2026-07-09).
> Owner: compat layer. This doc is the single source of truth for what CC Commander ships
> on each agent surface and what is still blocked upstream.

## TL;DR

ChatGPT Work (OpenAI's work-agent product, launched July 9, 2026, powered by GPT-5.6

CC Commander already targets or now targets with this compat layer:

## What ChatGPT Work is

- Launched **2026-07-09** alongside GPT-5.6 (Sol / Terra / Luna variants). An agent inside
  ChatGPT that gathers context across connected apps and returns finished docs, sheets,
  slides, and web apps. Rolling out desktop-first, then web/mobile for Plus, Pro, Business,
  Enterprise, Edu. ([Forbes, 2026-07-09](https://www.forbes.com/sites/madhulika-pathak/2026/07/09/openai-debuts-chatgpt-work-workplace-ai-agent-with-gpt-56/),
  [InfoWorld, 2026-07](https://www.infoworld.com/article/4195478/openai-launches-chatgpt-work-as-it-broadens-gpt-5-6-rollout.html))
- The Codex developer docs now live at `learn.chatgpt.com` (all
  `developers.openai.com/codex/*` URLs 308-redirect there) — the Codex CLI, the ChatGPT
  desktop app, and the IDE extension share one plugin/skill ecosystem.
  ([Plugins doc, accessed 2026-07-10](https://developers.openai.com/codex/plugins.md))
  Per that doc, plugins load in **"ChatGPT Work (web), ChatGPT Work/Codex (desktop app)"**,
  and **"Codex CLI and the IDE extension can also browse and install plugins."**

## Surface 1 — Plugins (`.codex-plugin/plugin.json`)

Verified schema ([build-plugins.md, accessed 2026-07-10](https://developers.openai.com/codex/build-plugins.md)):

- **Required manifest fields:** `name` (kebab-case), `version` (semver), `description`.
- **Component pointers:** `skills` (dir), `mcpServers` (`.mcp.json`), `hooks`
  (`hooks/hooks.json` or custom path), `apps` (`.app.json` — connector declaration).
- **Interface block:** `displayName`, `shortDescription`, `longDescription`,
  `developerName`, `category`, `capabilities`, `websiteURL`, `privacyPolicyURL`,
  `termsOfServiceURL`, `defaultPrompt` (**array of strings**), `brandColor`,
  `composerIcon`, `logo`, `screenshots`.
- **Local testing:** a repo marketplace at `$REPO_ROOT/.agents/plugins/marketplace.json`
  with a plugin entry whose `source.path` points at the plugin dir; or
  `codex plugin marketplace add <root>`.

**What CCC ships:**

- `commander/cowork-plugin-codex/.codex-plugin/plugin.json` — generated by
  `npm run build:codex` from the Claude manifest. This PR fixes `interface.defaultPrompt`
  to the documented array form (`["/ccc"]`).
- `.agents/plugins/marketplace.json` (repo root) — local plugin marketplace so a clone of
  this repo is directly installable in Codex CLI / ChatGPT desktop:

  ```bash
  git clone https://github.com/KevinZai/commander && cd commander
  codex plugin marketplace add .
  # then install "commander" from the plugin picker, or restart the ChatGPT desktop app
  ```

- Note: the mirror manifest also carries an `agents` pointer (`./agents/` with TOML
  personas). `agents` is **not** in the documented component-pointer list
  (skills/apps/mcpServers/hooks); unknown fields are tolerated, and subagents are
  documented separately ([subagents doc](https://developers.openai.com/codex/agent-configuration/subagents.md)).
  Treat it as best-effort until OpenAI documents plugin-bundled agents.

**Public distribution:** submission portal at `platform.openai.com/plugins`. Requirements
verified 2026-07-10 ([submit-plugins.md](https://developers.openai.com/codex/submit-plugins.md)):
verified developer/business identity, production MCP URL for app-based plugins, domain
verification token at `/.well-known/openai-apps-challenge`, tool annotations
(`readOnlyHint`, `openWorldHint`, `destructiveHint`), and **exactly 5 positive + 3 negative
test cases**. Approved plugins land in one **universal directory across ChatGPT and Codex**
(no separate enterprise directory). See gap **G3**.

## Surface 2 — Skills (`SKILL.md`)

Verified ([build-skills.md, accessed 2026-07-10](https://developers.openai.com/codex/build-skills.md)):

- Lookup chain: `$CWD/.agents/skills` → up to `$REPO_ROOT/.agents/skills` →
  `$HOME/.agents/skills` → `/etc/codex/skills` → bundled.
- `SKILL.md` frontmatter requires `name` + `description`; optional `scripts/`,
  `references/`, `assets/` dirs — **identical to the Claude Code skill format**, so CCC
  skills pass through byte-identical (that is exactly what `scripts/build-codex.js` does).
- Optional `agents/openai.yaml` per skill: UI metadata, `allow_implicit_invocation`,
  and MCP tool dependencies (`type: "mcp"`, `transport: "streamable_http"`, `url: …`).
- Skills work across **"the ChatGPT desktop app, Codex CLI, and IDE extension"**; invoke
  explicitly with `$skillname` or `/skills`.

**Install (per-skill, no plugin):**

```bash
# user-level: available in every project
mkdir -p ~/.agents/skills
cp -r commander/cowork-plugin-codex/skills/ccc-plan ~/.agents/skills/ccc-plan

# repo-level: available to anyone using ChatGPT Work / Codex in the repo
mkdir -p .agents/skills && cp -r <skill> .agents/skills/
```

## Surface 3 — AGENTS.md

Verified ([agents-md doc, accessed 2026-07-10](https://developers.openai.com/codex/agent-configuration/agents-md.md)):
global `~/.codex/AGENTS.md` (or `AGENTS.override.md`), then per-directory from Git root
down to `$CWD`; later files win; collection stops at `project_doc_max_bytes`
(**32 KiB default**, configurable in `~/.codex/config.toml`).

**What CCC ships:** `npm run build:codex` now emits a deterministic
`commander/cowork-plugin-codex/AGENTS.md` (well under 32 KiB) generated from
`commander/contract.json` + the plugin manifest, so any Codex/ChatGPT Work agent operating
in or installing from the mirror gets the CCC operating rules natively. Repos that adopt
CCC can copy it or symlink `AGENTS.md → CLAUDE.md` (see `compatibility/codex-config.md`).

## Surface 4 — MCP connectors / Apps SDK

Verified as of 2026-07-10:

- Apps in ChatGPT are built on **MCP** via the Apps SDK; "a plugin is the package users
  discover, install, submit, and publish — an app is the MCP-backed capability inside that
  package" ([build-app.md](https://developers.openai.com/codex/build-app.md),
  [Introducing apps in ChatGPT](https://openai.com/index/introducing-apps-in-chatgpt/)).
- Connecting a custom MCP server to ChatGPT: enable Developer mode, then add the server's
  **public HTTPS `/mcp` endpoint** at Settings → Plugins / chatgpt.com/plugins. Apps are
  supported on **all plans** (since 2025-11-13); Business/Enterprise/Edu workspaces gate
  custom connectors behind admin-enabled developer mode with RBAC
  ([connect-chatgpt](https://developers.openai.com/apps-sdk/deploy/connect-chatgpt),
  [developer mode help](https://help.openai.com/en/articles/12584461),
  [connectors help](https://help.openai.com/en/articles/11487775-connectors-in-chatgpt)).
- Transport is `streamable_http`; OAuth is the documented auth flow
  (`mcpServer/oauth/login` in the app-server API —
  [app-server.md](https://developers.openai.com/codex/app-server.md)).

**What CCC has today:**

| Piece | Path | ChatGPT Work-ready? |
|-------|------|--------------------|
| Local skill-bridge MCP (stdio) | `commander/mcp-server/index.js` | ✅ in Codex CLI via `[mcp_servers]` in `~/.codex/config.toml` (see `compatibility/chatgpt-work.md`) |
| Bundled credential-free MCPs | `commander/cowork-plugin-codex/.mcp.json` (context7, sequential-thinking) | ✅ ships inside the plugin |
| Hosted MCP | `apps/mcp-server-cloud/` → `https://mcp.commanderplugin.com` | 🟡 gap **G2 — code complete, pending deploy + issuer config**: `/mcp` streamable-HTTP endpoint (official MCP SDK transport, stateless) + OAuth 2.1 resource server (RFC 9728 metadata at `/.well-known/oauth-protected-resource`, external issuer via `OAUTH_ISSUER_URL`) built on branch `feat/mcp-streamable-oauth`; `/v1` + `/v1/sse` + `POST /v1/call` static-Bearer path unchanged for existing clients. Remaining: deploy + Kevin configures the OAuth issuer (see `apps/mcp-server-cloud/PAYWALL.md`) |
| Domain-verification route | `GET /.well-known/openai-apps-challenge` (added in this PR, serves `OPENAI_APPS_CHALLENGE_TOKEN`) | ✅ unblocks the submission prerequisite once a token is issued |

## Claude Cowork manifest compliance (re-verified 2026-07-10)

Checked against the current [Claude Code plugins reference](https://code.claude.com/docs/en/plugins-reference):

- Only `name` is required; CCC's `commander/cowork-plugin/.claude-plugin/plugin.json` is
  fully compliant. Unknown fields (e.g. `displayName`) are explicitly tolerated
  ("metadata from another ecosystem in `plugin.json` and the plugin still loads").
- `version` is pinned (good — omitting it makes every commit a new version).
- Optional fields worth adopting later (not needed now): `dependencies`
  (plugin-to-plugin), `defaultEnabled: false` (v2.1.154+, for opt-in cost plugins),
  `lspServers`, `experimental.monitors`.

| ID | Gap | Blocking dependency | Next action |
|----|-----|--------------------|-------------|
| **G1** | `apps` pointer + `.app.json` connector declaration not shipped | OpenAI has not published the `.app.json` schema — neither [build-app.md](https://developers.openai.com/codex/build-app.md) nor [app-server.md](https://developers.openai.com/codex/app-server.md) documents its fields (verified 2026-07-10) | Watch `learn.chatgpt.com/docs/build-plugins.md`; add `.app.json` + `apps` pointer to the codex mirror the day the schema lands |
| **G2** | Hosted MCP not connectable from ChatGPT — **code complete, pending deploy + issuer config** | ~~Transport + OAuth engineering~~ **Built** (branch `feat/mcp-streamable-oauth`): (a) `/mcp` streamable-HTTP via the official MCP SDK transport (stateless, same 18 tools, `/v1` untouched); (b) OAuth 2.1 resource-server — RFC 9728 protected-resource metadata + external-issuer JWT validation (JWKS), tokens map to the same key records as `/v1` Bearer. Remaining dependency: deploy to Fly + Kevin configures `OAUTH_ISSUER_URL`/`OAUTH_RESOURCE_URL` and an AS supporting auth-code + PKCE (setup: `apps/mcp-server-cloud/PAYWALL.md` §3) | Merge + deploy, configure issuer, then verify the connector flow end-to-end from ChatGPT Developer mode |
| **G3** | Not in the universal ChatGPT/Codex plugin directory | Submission requires verified identity, production MCP URL (needs G2), domain-verification token live at `/.well-known/openai-apps-challenge` (route ships in this PR; token must be issued from the portal), 5+3 test cases | Kevin: complete identity verification at `platform.openai.com/plugins`, then submit after G2 |
| **G4** | Hook parity — 17 Claude lifecycle events dropped in the codex build | Codex hook surface only documents SessionStart-class events; `scripts/build-codex.js` intentionally drops unsupported events | Re-audit `HOOK_EVENTS_DROPPED_BY_BUILD` when OpenAI expands hook events |
| **G5** | Per-skill `agents/openai.yaml` metadata (icons, implicit-invocation policy, MCP deps) not emitted | Buildable today, but low-value until CCC skills declare MCP dependencies per-skill | Fold into `build-codex.js` when a skill actually needs `streamable_http` tool deps |

## Validation

`node scripts/check-compat.js` (added in this PR, wired for CI) validates every manifest

`AGENTS.md` (present, < 32 KiB), and `.agents/plugins/marketplace.json` source paths.
