# 🎭 How users browse skills

CC Commander ships **two parallel discovery surfaces**. They serve the same skill catalog but are shaped by what each client supports.

<Note>
  **Current status:** the hosted MCP server at `mcp.commanderplugin.com` is live. Plugin install works in Claude Code today; MCP access for Cursor/Windsurf/Cline/Continue/Codex/Claude mobile goes through the hosted endpoint below, which requires a CC Commander access token. Self-serve token issuance isn't live yet.
</Note>

## The split in one sentence

| Client | How to browse | Mechanism |
|--------|---------------|-----------|
| **Claude Cowork Desktop (plugin)** ⭐ | `/ccc-<name>` slash commands — ideal for novices, zero config | Plugin manifest `skills: "./skills/"` |
| **Claude Code Desktop (plugin)** | Same as above — identical install path | Plugin manifest `skills: "./skills/"` |
| **Claude Code CLI (terminal)** | `ccc` interactive TUI + slash commands in CC sessions | CLI binary + plugin |
| **Cursor / Windsurf / Cline / Continue / Codex / Claude mobile** | Agent calls `list_skills` / `search_skills` / `suggest_skill` on the user's behalf | Hosted MCP server at `mcp.commanderplugin.com` |

Same 467+ skills. Different UX glue.

<Info>
  **New to AI coding agents?** Start with **Claude Cowork Desktop** — it's designed for novice users and CC Commander's guided workflows are perfect for learning by doing. The plugin install is identical to Claude Code Desktop; Cowork just surfaces agent coordination more prominently in its UI.
</Info>

## Native plugin (Claude Code)

When you `/plugin install commander --marketplace KevinZai/commander` in Claude Code, the plugin manifest registers:
- **93 plugin skills** as plain `/ccc-*` slash commands (no namespace prefix) — all core free forever
- **22 specialist agents** available via the Agent tool (architect, security-auditor, builder, reviewer, etc.)
- **30 lifecycle hooks × 51 handlers** (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PermissionDenied, model switches, Stop, compaction, subagents and more)
- **2 credential-free bundled MCP servers** (`context7` + `sequential-thinking`) + 16 opt-in via `/ccc-connect` (Linear, Supabase, Vercel, Slack, Notion, Sentry and more)

**Pros:** tab-completion, instant discovery, deep Claude Code integration, offline-capable, lifecycle hooks.
**Cons:** Claude Code only — can't use in Cursor, Windsurf, etc.

```bash
/plugin install commander --marketplace KevinZai/commander
# Type /ccc-  to see the full slash menu
```

### The v7 Browse experience — `/ccc-browse` and the Commander Cockpit

Since v7.0.0, `/ccc-browse` is a scannable skill LIST built for finding a skill fast, not a wall of one-skill "domains":

- **Rows / tiles toggle** — switch layouts; your choice is persisted across sessions.
- **Live filter** — real-time filtering on name, purpose, or domain as you type, plus compact domain-filter chips (`all · 533`, `marketing · 46` … `general · 257`).
- **Copy-on-click** — clicking a whole row copies the command instead of requiring a precise click target.
- **Honest taxonomy** — the Cockpit's browse taxonomy has **14 real display domains**: plugin `/ccc-*` commands collapse into one **commands** front-door group (not ~78 one-skill "domains"), ungrouped ecosystem skills route to an honest **general** bucket (sorted last), and domain routers living in `skills/ccc-X/` are grouped as `ccc-X`. No misleading "core" catch-all. (This 14-domain browse taxonomy is a Cockpit display concept — distinct from the 11 canonical CCC domain routers documented in [Plugin Skills](/plugin/skills).)
- **🎛️ Open the Commander Cockpit** — the same picker's top option publishes the full catalog as a self-contained, clickable artifact (skill/agent browser, prompt enhancer, agent analytics, Tools tab), carrying the shared **Commander decks** switcher to jump to Mission Control, Usage & Cost, or Safety.

## Hosted MCP server (every other AI IDE)

Cursor, Windsurf, Cline, Continue, Codex, Claude mobile, Claude Desktop, and any future MCP-capable client point at `https://mcp.commanderplugin.com/mcp` (Streamable HTTP, Bearer token). The same 467+ skill catalog becomes available through the tools below.

**Pros:** works in any MCP-capable client, zero install on user's machine, lazy-loads skills (only the ones invoked hit the wire), one URL plus a Bearer token header.
**Cons:** requires a CC Commander access token (no OAuth sign-in yet; the server's RFC 9728 metadata lists no authorization server), requires network round-trip, no slash-command autocomplete (agent-mediated only), no lifecycle hooks (MCP is request/response).

```json
// ~/.cursor/mcp.json (example — Cursor users)
{
  "mcpServers": {
    "cc-commander": {
      "url": "https://mcp.commanderplugin.com/mcp",
      "headers": {
        "Authorization": "Bearer ${env:COMMANDER_TOKEN}"
      }
    }
  }
}
```

## Hybrid: plugin + MCP together (recommended for Claude Code power users)

Claude Code users can install the plugin **and** point at the hosted MCP. Benefits:

1. **Lazy-load 467+ deeper skills** without bloating the plugin manifest — e.g. `ccc-marketing` plugin skill routes to one of 45 marketing sub-skills via MCP, loaded on demand.
2. **Cross-session usage counter** — the same 100-call/month anti-abuse cap applies wherever you call the hosted MCP from.
3. **Unified feedback history** — surveys you've filled out in Claude Code count in Cursor.
4. **Preserve muscle memory** — `/ccc-design` still works. Under the hood it queries the MCP. From your perspective nothing changes.

To enable hybrid on Claude Code:
```bash
/plugin install commander --marketplace KevinZai/commander   # already done? you're ready
# then add the hosted MCP (Streamable HTTP + Bearer token) to Claude Code:
claude mcp add --transport http cc-commander https://mcp.commanderplugin.com/mcp \
  --header "Authorization: Bearer $COMMANDER_TOKEN"
```

## What does NOT work in MCP that works in plugin

- **Autocomplete UI** — MCP has no way to inject `/slash` commands into a non-plugin client's command palette. The agent has to surface skills in prose when asked.
- **Lifecycle hooks** — plugin has 30 hook events (SessionStart, PreToolUse, PostCompact, etc.). MCP is request/response — no "run when session starts" primitive in most clients yet. When [Anthropic ships PostCompact and Elicitation events on MCP](https://modelcontextprotocol.io/specification), we'll bridge them.

## What does NOT work in plugin that works in MCP

- **Cross-IDE identity** — plugin runs per-editor; MCP is centralized.
- **Zero-install** — plugin requires file download + Claude Code version compat; MCP is a URL.
- **Live skill updates** — plugin updates need `/plugin update commander`; MCP skill catalog is always current.
