# ⬆️ Upgrade to v8.1.0

You already have CC Commander installed? Here's how to pick up v8.1.0 with zero drama.

<Warning>
  Third-party plugin marketplaces do **not** auto-refresh by default. If you
  only run `/plugin update commander`, it updates against whatever your
  **local marketplace clone** last synced — which can be weeks stale. Run
  the marketplace refresh first, every time.
</Warning>

## Claude Code Desktop / CLI (plugin)

```
/plugin marketplace update commander-hub
/plugin update commander
```

Step 1 refreshes the local marketplace clone from `KevinZai/commander`'s
`main` branch. Step 2 then actually updates the installed plugin — it can
only pull a version that step 1 just fetched.

**CLI one-liner** (same two steps):

```bash
claude plugin marketplace update commander-hub && claude plugin update commander
```

<Note>
  **Restart required.** `/plugin update` stages the new version — it does
  not hot-swap the running session. Fully quit Claude Code / Cowork Desktop
  (Cmd+Q, not just closing the window — the menu-bar process must exit) and
  reopen, or start a new CLI session.
</Note>

### Skip step 1 next time (auto-update)

Third-party marketplaces support an opt-in auto-refresh flag. Set
`"autoUpdate": true` on the `commander-hub` entry in
`~/.claude/plugins/known_marketplaces.json`:

```json
{
  "commander-hub": {
    "source": { "source": "github", "repo": "KevinZai/commander" },
    "installLocation": "~/.claude/plugins/marketplaces/commander-hub",
    "autoUpdate": true
  }
}
```

Preserve every other key already in that entry — only add `autoUpdate`.
Or run `/ccc-doctor`, which offers to do this for you (backs up the file
first, asks for confirmation, verifies the write). Some Claude Code builds
also expose this as a toggle in the `/plugin` interactive menu — check
there first if you'd rather not hand-edit JSON.

With `autoUpdate: true`, the marketplace clone still refreshes in the
background rather than instantly — `/plugin update commander` (step 2, plus
the restart) still applies it.

### Click-first walkthrough

Prefer not to run commands by hand? `/ccc-update` detects your installed
vs. latest version, runs both commands for you to confirm, reminds you to
restart, and verifies the new version + hooks are actually live afterward.

### Verify the upgrade

```
/plugin list | grep commander
# should show the latest version (currently v8.1.0), Kevin Zicherman
```

Or in a fresh Claude Code session:

```
/ccc-settings
```

The settings menu header reports the installed version. You can also run `/ccc-doctor` — it validates the plugin manifest and reports drift against expected canonical counts.

### What changes for you

The 8.1.0 release adds descriptive MCP tool annotations, JSON-RPC catalog discovery,
and cloud test/startup fixes. Existing force-push denials remain unchanged.
The table below includes the v8 platform changes for users upgrading from v7.

| Surface | Before (v7.4.2) | Now (v8.1.0) |
|---------|-----------------|----------------------|
| Plugin skills | 83 | 84 (new: `/ccc-codex`) |
| Agents | 22 specialist personas | 22, on model aliases (`fable`, `opus`, `sonnet`) |
| Hooks | 23 lifecycle events / 44 handlers | 30 lifecycle events / 51 handlers |
| Plugin workflows | 4 | 6, runnable as `/commander:<name>` |
| Plugin evals | — | 8 `claude plugin eval` cases |
| Mods | — | Commander HUD (Claude Code 2.1.287+) |
| Models | Previous Claude and Codex generations, partly pinned ids | Opus 5.5, Fable 5.1, Sonnet 5.5, Haiku 5.5; GPT-6 family on Codex |
| Bundled MCP servers | 2 credential-free + 16 opt-in | 2 credential-free + 16 opt-in (unchanged) |
| Ecosystem skills | 467 | 467 (unchanged) |

If you pinned old model ids in your own `~/.claude/settings.json` or agent files, `/ccc-doctor` flags superseded ids as upgrade candidates; Commander's own files now use aliases.

Your `~/.claude/commander/` state files, knowledge base, and learned-skills directory are preserved. No data migration needed.

## CLI toolkit

```bash
curl -fsSL https://raw.githubusercontent.com/KevinZai/commander/main/install-remote.sh | bash
ccc --version   # should show the latest version (currently 8.1.0)
```

Re-run the post-install verify:

```bash
ccc --test      # runs the full test suite
ccc --status    # shows plugin + cli + vendor + tests + integrations
```

## If you built from source

If you cloned the repo or use the curl installer:

```bash
cd ~/path/to/commander   # or wherever you cloned
git pull origin main
git submodule update --init --recursive   # pick up vendor updates
npm install
npm test
```

Or the one-liner reinstall:

```bash
curl -fsSL https://raw.githubusercontent.com/KevinZai/commander/main/install-remote.sh | bash
```

## Rollback

If something breaks (please file an issue first):

```
/plugin update commander --version 7.4.2
# or
git clone --branch v7.4.2 https://github.com/KevinZai/commander && cd commander && ./install.sh
```

## After the upgrade

Optional but recommended: run `/ccc-tuneup` to audit your local `~/.claude` setup (versions, drift, superseded agents, hooks coverage) or `/ccc-claudemd` to refresh your project `CLAUDE.md` against current conventions. Custom sections are preserved.
