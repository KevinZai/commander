CC Commander's plugin architecture is based on Anthropic's **Agent Skills spec**, which OpenAI adopted in December 2025. This means SKILL.md files — the core of the plugin — port to Codex with zero changes.

<Note>
  **Status (v6.0.0):** Codex CLI and Codex Desktop compatibility is shipping as a generated mirror at `commander/cowork-plugin-codex/`. The canonical source remains `commander/cowork-plugin/`; run `npm run build:codex` to regenerate the Codex artifact.
</Note>

## What works today

| CC Commander component | Codex status | Notes |
|------------------------|-------------|-------|
| `skills/*/SKILL.md` | ✅ 1:1 port | 62 skills pass through byte-for-byte from the Claude plugin tree |
| `.mcp.json` MCP server configs | ✅ Compatible | The 2 bundled MCP servers, `context7` and `sequential-thinking`, pass through |
| `hooks.json` | ✅ Supported subset | Codex artifact emits `PermissionRequest`, `PostToolUse`, `PreToolUse`, `SessionStart`, `Stop`, and `UserPromptSubmit` |
| `agents/*.md` persona files | ✅ Translated | 22 Markdown-frontmatter agents become Codex `agents/*.toml` files |
| `.claude-plugin/plugin.json` | ✅ Translated | Becomes `.codex-plugin/plugin.json` with Codex paths for skills, agents, hooks, and MCP |
| `AskUserQuestion` (chip pickers) | ✅ Compatible | Codex ships `ask_user_question` with single/multi-choice and custom-option modes |

## What drops on the floor

Several Claude Code-specific lifecycle events have no Codex equivalent and are intentionally filtered during the build:

- `Notification` — Codex doesn't fire this event
- `PreCompact` — no context compaction concept in Codex
- `SubagentStop` — Codex uses a different subagent lifecycle model
- `PostCompact`, `SubagentStart`, `SessionEnd`, `StopFailure`, `PostToolUseFailure`, `PostToolBatch`, `Elicitation`, `ElicitationResult`, `TaskCreated`, `TaskCompleted`, `ConfigChange`, `UserPromptExpansion`, `InstructionsLoaded`, and `Setup` — no matching Codex plugin event in the generated artifact

These affect lifecycle automation only. Core `/ccc-*` skills, specialist agents, and bundled MCP servers remain available in the Codex mirror.

## Build and verify

Regenerate the Codex plugin mirror from the repo root:

```bash
npm run build:codex
```

The build reads `commander/cowork-plugin/` and writes `commander/cowork-plugin-codex/`, including `.codex-plugin/plugin.json`, `skills/`, `agents/`, `hooks.json`, `.mcp.json`, `lib/`, `menus/`, and `rules/`.

Verify the generated artifact:

```bash
node --test commander/tests/codex-build.test.js
```

## v6.0.0 release note

v6.0.0 makes the Codex adapter a first-class release surface: Commander now publishes a mechanically generated Codex plugin mirror from the canonical Claude plugin tree. Skills stay source-compatible, agents are converted to TOML, unsupported hooks are dropped explicitly, and the bundled MCP config is carried forward.

For users, the practical message is simple: install Commander where you work. Claude Code Desktop remains the primary product surface, and Codex CLI/Desktop now gets the same `/ccc-*` workflow catalog through the generated adapter.
