## Brain / Hands

CC Commander follows a **brain/hands** separation pattern built on Anthropic's Claude Agent SDK:

- **Brain (Claude):** The main Claude Code session reads project context, routes intent, and makes decisions
- **Hands (CC Commander):** Skills, hooks, and sub-agent personas execute the work — scoped, specialized, and disposable

When you invoke `/ccc-review`, Claude isn't guessing how to do a code review. It loads the `reviewer` persona (Sonnet, read-only tools, structured severity format) and delegates. When it finishes, the persona is gone. The next task starts fresh.

This keeps context clean, prevents drift, and means each specialist operates at full capacity instead of a generalist stretched thin.

## Built on the Claude Agent SDK

CC Commander's sub-agent architecture follows the same pattern Anthropic describes in their [Claude Agent SDK](https://docs.anthropic.com/en/docs/about-claude/models). Each plugin skill is a lightweight orchestration layer that:

1. Reads project state (git diff, file structure, active tasks)
2. Selects the right specialist persona
3. Delegates with a scoped tool allowlist and turn budget
4. Returns structured output to the main session

The plugin itself requires no external server, no API key, and no network call. It runs fully offline via the plugin manifest — the Claude Agent SDK pattern is implemented as skill files and hook scripts that Claude Code executes natively.

## 23 Lifecycle Hooks / 42 Handlers

Hooks fire automatically around Claude Code sessions. v5.1.0 expanded the system from 9 to 23 events. Each hook event can have multiple handlers.

**Core events:**

| Event | Handlers | What fires |
|-------|----------|-----------|
| `SessionStart` | 4 | Load context, stale CLAUDE.md nudge, post-compact recovery, ambient suggestion |
| `SessionEnd` | 2 | Session save + summary (moved from `Stop` in v5.1.0 — correctness fix) |
| `UserPromptSubmit` | 4 | Intent classifier, context budget check, suggest ticker, prompt logger |
| `PreToolUse` | 3 | Cost tracker + cost ceiling + secret leak guard |
| `PostToolUse` | 3 | Knowledge capture + quality gate + auto-format |
| `Stop` | 1 | Legacy cleanup |
| `Notification` | 1 | Fleet agent completion log |
| `PreCompact` | 1 | State save before context compaction |
| `PostCompact` | 1 | Context restoration hints |
| `SubagentStart` | 1 | Spawn time tracking |
| `SubagentStop` | 1 | Sub-agent cost aggregation |
| `PermissionRequest` | 1 | Nightwatch mobile relay |
| `TaskCreated` | 1 | Background workflow/task start |
| `TaskCompleted` | 1 | Background workflow/task finish |

9 additional events added in v5.1.0: `StopFailure`, `PostToolUseFailure`, `PostToolBatch`, `Elicitation`, `ElicitationResult`, `ConfigChange`, `UserPromptExpansion`, `InstructionsLoaded`, `Setup`.

All hooks fail gracefully — if a hook errors, the session continues. Hook state lives in `~/.claude/commander/` and never touches other `.claude/` contents. See [Hooks 2026](/hooks-2026) for the full registry.

## Dynamic Workflows (Research Preview)

v5.1.0 adds a second execution path for skills that need parallel subagents: **dynamic workflows**. A workflow is a JS file the runtime executes in the background, spawning many subagents concurrently and merging their findings.

CC Commander ships 4 bundled workflows:

| Workflow | Used by |
|----------|---------|
| `ccc-audit` | `/ccc-xray` |
| `ccc-deep-review` | `/ccc-review` |
| `ccc-migrate` | `/ccc-build` migrate mode |
| `ccc-fleet` | `/ccc-fleet` |

Requires Claude Code v2.1.154+. Skills fall back to standard `Agent()` dispatch on older clients. See [Dynamic Workflows](/dynamic-workflows) for the developer reference.

## Data Flow

**Standard (Agent dispatch):**

```
User prompt
    ↓
SessionStart hook (context loaded)
    ↓
UserPromptSubmit hook (intent classified → skill suggested)
    ↓
Skill invoked (e.g. /ccc-review)
    ↓
Skill reads project state + selects persona
    ↓
Sub-agent spawned with scoped tools + turn budget
    ↓
Sub-agent executes → structured output returned
    ↓
PostToolUse hook (knowledge captured)
    ↓
Main session resumes with result
    ↓
SessionEnd hook (session saved)
```

**Workflow path (Claude Code v2.1.154+):**

```
Skill invoked (e.g. /ccc-xray)
    ↓
TaskCreated hook fires
    ↓
Workflow script launched in background
    ↓
N subagents spawn in parallel (each a Sonnet reviewer)
    ↓
Findings merged + cross-validated
    ↓
TaskCompleted hook fires
    ↓
Structured result returned to main session
```

## Offline-First

The entire plugin works without any network connection. Skills, personas, and hooks are plain markdown + JavaScript files executed natively by Claude Code. The bundled `.mcp.json` adds 2 credential-free servers (`context7`, `sequential-thinking`); 16 more external integrations (Linear, GitHub, Slack, etc.) connect separately, opt-in via `/ccc-connect` — none of them are required, the plugin is fully functional without any of them.

See [vs aider.chat](/compare/vs-aider) for a direct positioning comparison.
