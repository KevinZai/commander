## What is ultracode?

Ultracode is a Claude Code toggle, separate from reasoning effort. With it on, Claude plans a dynamic workflow for each substantial task — fan out to many agents, verify their findings adversarially, synthesize — instead of a single-agent pass.

Since Claude Code 2.1.284, `/effort ultracode` is **its own toggle**. It no longer forces a reasoning level. You set the two dials independently:

| Dial | Command | Effect |
|---|---|---|
| Ultracode | `/effort ultracode on` · `/effort ultracode off` | Plan a verified workflow for each substantial task |
| Reasoning effort | `/effort high` · `/effort xhigh` · `/effort max` | How long the model thinks per turn. `max` lasts only for the current session |

Check the current state with `/effort`. Both dials are typed by you; no skill can flip them for you.

## Three ways to get workflow depth

**1. The toggle, for a deep session:**

```
/effort ultracode on
```

Turn it off with `/effort ultracode off` when the deep work is done.

**2. The skill, for a guided run:**

```
/ccc-ultracode
```

`/ccc-ultracode` reads your branch and diff, offers a picker (deep repo audit, deep branch review, codebase migration, multi-agent fleet), asks only for what has no safe default, and launches the matching bundled workflow. Research questions go to `/deep-research` instead.

**3. One task, no mode change:**

Include the word `workflow` in the prompt:

```
workflow: refactor the auth module to use the new session strategy
```

Or run a bundled workflow directly as `/commander:<name>` — see [Dynamic Workflows](/dynamic-workflows).

## Reasoning effort levels

The effort levels are `low`, `medium`, `high`, `xhigh` and `max`.

| Level | When to use |
|-------|------------|
| `max` | Architecture decisions, complex security audits, multi-system migrations (session-scoped) |
| `xhigh` | Hard builds, reviews and audits |
| `high` | General development |
| `medium` | Fast iteration, bulk work |
| `low` | Mechanical edits |

Commander's skills also pass an effort level per dispatch through the Agent tool's `effort` parameter, so a quick router stays fast while a verifier thinks hard.

## When to use it

- **Use** for migrations across many files, audits where false positives waste time, repo-wide cleanups, design stress-tests, and plans worth checking from several angles.
- **Skip** for routine edits, single-file fixes, quick questions, and anything where speed matters more than depth.

| Skill | What workflow depth means here |
|-------|-----------------|
| `/ccc-xray` | Runs the `ccc-audit` workflow — one finder per dimension, every finding verified |
| `/ccc-review` | Runs `ccc-deep-review` — four weighted dimensions in parallel |
| `/ccc-fleet` | Fan-out, pipeline, judge panel or debate |
| `/ccc-research` | Hands off to `/deep-research` for cited multi-source research |

## Cost awareness

A workflow spawns many agents; a full-repo audit can cost ten to fifty times a single pass. Scope to a path first.

Commander's `cost-ceiling-enforcer.js` hook tracks a session **tool-call budget** (an activity metric, not dollars). It is off by default. Turn it on with `CCC_COST_CEILING=<units>` (1.00 = 100 tool calls; `0` or `off` turns it back off) or `costCeiling` in `<config dir>/commander/config.json` (`~/.claude/commander/config.json` for the default lane). Once set, the first crossing warns and each later tool call is denied with the reason, unless `CCC_COST_OVERRIDE=1` is set:

```json
{
  "costCeiling": 20.00
}
```

The Commander HUD mod shows the session's tool-call budget above the prompt on Claude Code 2.1.287+.
