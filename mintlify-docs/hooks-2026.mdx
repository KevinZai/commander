## Events Commander deliberately leaves alone

Claude Code exposes three events beyond the 30 Commander registers. Each is skipped on purpose:

- **`WorktreeCreate`** is not a telemetry hook. Registering one *replaces* git worktree creation: the hook itself must create the working copy and print its path, and if it fails or prints nothing, worktree creation fails. A plugin that only wanted to observe would break `/ccc-fleet`, `isolation: worktree` subagents and every workflow that runs in a worktree.
- **`WorktreeRemove`** has the same shape: exit 0 counts as "removed" and git's own cleanup is skipped, so an observing hook would leak worktrees.
- **`MessageDisplay`** rewrites what is shown for a message. Commander has nothing to change there.

## Codex mirror: 12 events

The generated Codex plugin (`commander/cowork-plugin-codex/`) carries the handlers for the 12 events Codex CLI supports: `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `UserPromptSubmit`, `SubagentStart`, `SubagentStop`, `Stop`, `SessionStart`, `SessionEnd` and `Interrupt`. Events Codex lacks are dropped by `scripts/build-codex.js` using `hook-event-map.json`. Timeouts ship in seconds, `SessionEnd` is capped at Codex's 3-second limit, and `Interrupt` has no Claude source, so no handler is mapped to it. Codex treats plugin hooks as untrusted until you review them with `/hooks`.

## Handler conventions

- **Shell form, quoted root.** Every command is `node "${CLAUDE_PLUGIN_ROOT}/hooks/<script>.js"`. The quotes matter: Desktop installs live under a path with a space. Shell form (rather than `args`) keeps one `hooks.json` that also mirrors to Codex.
- **Fail-open.** Telemetry handlers always exit 0 and never block. Only the guards (`secret-leak-guard.js`, `config-protection.js`, `cost-ceiling-enforcer.js`, `permission-gate.js`) can deny a tool call.
- **Async where nothing waits.** Writers such as `mission-control-feed.js`, `task-tracker.js`, `fleet-notify.js` and `update-nudge.js` run with `"async": true`.
- **Local writes only.** Every handler writes under `~/.claude/commander/`.

## Disabling individual hooks

To disable a hook event without uninstalling the plugin:

```json
// ~/.claude/commander/config.json
{
  "hooks": {
    "PostToolUseFailure": false,
    "Elicitation": false,
    "ConfigChange": false
  }
}
```

Disabling an event disables all its handlers. Run `/hooks` inside Claude Code to see every configured hook by event.

## State layout

Hook state lives in `~/.claude/commander/` and never touches other `.claude/` contents:

```
~/.claude/commander/
├── sessions/
│   ├── active-session.json       # current session (SessionStart, CwdChanged, DirectoryAdded)
│   ├── active-cost.json          # incremented on each PreToolUse
│   └── YYYY-MM-DD-{hash}.json    # archived on SessionEnd
├── analytics/
│   └── permission-gate.jsonl     # permission decisions + auto-mode denials (PermissionDenied)
├── knowledge/
│   ├── auto-captures.jsonl       # file-touch observations (PostToolUse)
│   └── {timestamp}.json          # manual lessons via /ccc-knowledge
├── fleet/
│   ├── notifications.jsonl       # fleet task completion log
│   └── teammates.jsonl           # teammate idle events (TeammateIdle)
├── model-switches.jsonl          # PreModelSwitch / PostModelSwitch
├── tasks/
│   └── active-tasks.json         # in-flight background tasks
├── pre-compact/                  # state before compaction (PreCompact)
├── post-compact/                 # context restoration hints (PostCompact)
└── config.json                   # user settings
```

## Execution model

Hooks are Node scripts run by Claude Code's hook runtime:

1. Receive the event context as JSON on stdin.
2. Run their logic (typically 5–50 ms).
3. Print nothing, or a JSON object with the fields that event accepts (for example `hookSpecificOutput.additionalContext`, `permissionDecision` on `PreToolUse`, `systemMessage` on `FileChanged`).

`PreModelSwitch` handlers are kept fast on purpose: a `PreModelSwitch` hook that times out blocks the switch.

## Privacy

Hooks store state locally at `~/.claude/commander/`. Anonymous event telemetry (event name, hook name, OS, plugin version) is off by default and sent only if you opt in:

```bash
# Opt in to telemetry
CCC_TELEMETRY=1 claude
# Opt in to the CI status lookup (gh run list with your own gh login)
CCC_CI_TICKER=1 claude
# Block every outbound call (telemetry, update check, CI lookup)
CCC_OFFLINE=1 claude
```

Each variable accepts `1`, `true`, `yes` or `on` to turn it on and `0`, `false`, `no` or `off` to turn it off (any case). No prompts, file contents or paths are ever transmitted. The session-start update check (a GET of the public `plugin.json` on GitHub) is the only call on by default. `ccc doctor` prints the current mode. Opted-in events go to the hosted server at `mcp.commanderplugin.com`, a separate service covered by the [privacy policy](https://commanderplugin.com/privacy).

## Defaults worth knowing

- **Cost ceiling:** `cost-ceiling-enforcer.js` is off unless `CCC_COST_CEILING=<units>` or `costCeiling` in the lane config is set (`0` or `off` disables it). When it trips it returns a `PreToolUse` deny with a readable reason and names the lane config file it read.
- **Voice layer:** `voice-injector.js` emits nothing unless the env var `CCC_VOICE` is `1`, `true`, `yes` or `on`, or `"voice": true` is set in the lane config file `<config dir>/commander/config.json` (`~/.claude/commander/config.json` for the default lane). `CCC_VOICE_DISABLE=1` or `CCC_VOICE=0` turns it off.
- **Lanes:** `commander/lib/lane.js` is the one lane resolver (`CCC_CONFIG_DIR` > `CLAUDE_CONFIG_DIR` > `~/.claude`). Aliases come from its default table (`guestnetworks` → `ai5`) overlaid by `lanes.aliases` in `~/.commander/config.json`; the status line and `ccc doctor --instances` read the same table.
