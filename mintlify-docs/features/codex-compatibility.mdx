CC Commander's plugin is built on Anthropic's **Agent Skills spec**, which OpenAI adopted for Codex. SKILL.md files — the core of the plugin — port to Codex with almost no changes.

<Note>
  **Status (v8.0.0):** Codex CLI and Codex Desktop compatibility ships as a generated mirror at `commander/cowork-plugin-codex/`. The canonical source remains `commander/cowork-plugin/`; `npm run build:codex` regenerates the mirror. Install with `codex plugin marketplace add KevinZai/commander`, then `codex plugin add commander@commander-hub`.
</Note>

<Warning>
  **Hook trust gate:** installing or enabling this plugin does **not** automatically trust its hooks. Codex skips plugin-bundled hooks until you review and trust them with `/hooks` inside Codex. If Commander's hooks (skill-run logging, cost tracking, Mission Control feed) don't seem to fire after install, this is almost always why.
</Warning>

## What changed in v8.0.0

- **Twelve Codex events.** Codex now supports `SessionEnd` and `Interrupt`, so the mirror keeps Commander's `SessionEnd` handlers. The event map (`commander/adapters/codex/hook-event-map.json`) drives which Claude events are dropped.
- **Timeouts in seconds,** with Codex's 3-second cap on `SessionEnd`.
- **TOML subagents.** `scripts/build-codex.js` emits valid TOML agents from the plugin's agent files, with models resolved through the registry. `/ccc-codex` installs them into `~/.codex/agents/`.
- **Current models.** Deep and verification work routes to `gpt-6-astra`, the default executor is `gpt-6.1-sol`, bounded implementation is `gpt-6-sol`, and mechanical work is `gpt-6-luna`.
- **Manifest.** The plugin carries the `com.openai` interface extension and the marketplace entry uses the current source, policy and category schema. `mods/`, `evals/` and `workflows/` are never copied into the mirror.

`${CLAUDE_PLUGIN_ROOT}` is left verbatim: Codex exposes its native `PLUGIN_ROOT` / `PLUGIN_DATA` env vars plus `CLAUDE_PLUGIN_ROOT` / `CLAUDE_PLUGIN_DATA` as documented compatibility aliases.

## What still doesn't port

Claude Code has hook events, and two capabilities referenced from skill prose, with no Codex equivalent:

| Claude Code capability | Codex status | What the Codex mirror does instead |
|---|---|---|
| `Notification`, `PostToolUseFailure`, `PostToolBatch`, `StopFailure` hooks | ❌ not in Codex's hook surface | dropped on translate |
| `Elicitation`, `ElicitationResult`, `TaskCreated`, `TaskCompleted`, `TeammateIdle`, `ConfigChange`, `UserPromptExpansion`, `InstructionsLoaded`, `Setup`, `PermissionDenied`, `PreModelSwitch`, `PostModelSwitch`, `CwdChanged`, `DirectoryAdded`, `FileChanged` hooks | ❌ Claude-only events | dropped on translate |
| Claude Mods (the Commander HUD) | ❌ Claude Code only | `mods/` is not copied |
| Plugin workflows and evals | ❌ Claude Code only | `workflows/` and `evals/` are not copied |
| Hook handlers with `"async": true` | parsed but **skipped** — "asynchronous command hooks aren't supported yet" | `async` flag is stripped; the handler still runs, now synchronously, with its timeout in seconds |
| `AskUserQuestion` (chip picker) | ❌ no Codex equivalent | every skill that references it gets one appended note: *"On Codex, present these options as a numbered list and ask the user to reply with a number — AskUserQuestion is Claude-only."* |
| `Workflow(...)` tool | ❌ not packaged for Codex | every skill that references it gets one appended note: *"The Workflow(...) tool is not available on Codex — run the steps sequentially."* |

| CC Commander component | Codex status | Notes |

## Build and verify

Regenerate the Codex plugin mirror from the repo root:

```bash
npm run build:codex
```

The build reads `commander/cowork-plugin/` and writes `commander/cowork-plugin-codex/`, including `.codex-plugin/plugin.json`, `skills/`, `agents/`, `hooks.json`, `.mcp.json`, `lib/`, `menus/`, and `rules/`.

Verify the generated artifact:

```bash
node --test commander/tests/codex-build.test.js commander/tests/codex-extensions.test.js
node scripts/check-compat.js
```

## ask-bridge.js: experimental, not shipped

`commander/adapters/codex/ask-bridge.js` is a speculative bridge to Codex Desktop's `tool/requestUserInput` App Server method, written from documentation research rather than validation against a live Desktop instance. Every wire-format assumption in the file is marked inline. It is **not wired into `build-codex.js`** and does not ship in the generated mirror — treat it as a research prototype, not a working feature, until validated against a real Codex Desktop App Server pipe.
