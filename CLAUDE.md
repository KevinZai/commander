# CLAUDE.md — CC Commander

## Product and source of truth

CC Commander is a PM and orchestration layer over Claude's agent capabilities. The primary product is the Desktop plugin at `commander/cowork-plugin/`; the CLI toolkit and Codex adapter are additional supported surfaces. Core skills, agents, hooks, and connectors remain free. Revenue comes from disclosed affiliates, consulting, an optional community, and sponsorship; preserve the public product's portability and opt-in integrations.

Version: read `package.json`. Release history: `CHANGELOG.md`. Product/install guidance: `README.md`. For current skills, agents, hooks, and connectors, inspect the source directories, plugin manifest, and `CONNECTORS.md`; do not copy volatile counts into instructions. Historical prose is retained in [docs/reference/claude-context-2026-09-05.md](docs/reference/claude-context-2026-09-05.md), for reference only.

## Session behavior

Start from the user's request. Read relevant source and applicable instructions before editing; a small edit does not require a repository-wide scan. Reuse existing authorization and ask only about material unresolved decisions or required authorization. Do not add greetings, status footers, tracker pulses, or menu prompts as an incidental response to ordinary work.

Its text preserves the chosen model, points to Fable 5.1 for demanding reasoning, and keeps footer output conditional on a status/menu request. Inspect effective hook/settings state when diagnosing startup behavior; Markdown does not change permission controls or runtime enforcement. For ordinary work, enter plan mode only when requested or when a material design decision requires it.

Keep `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` enabled where the installed `/ccc-fleet` and dynamic-workflow implementation requires it; do not alter runtime settings as an incidental documentation fix. Tool availability is session-specific: use the exposed Workflow/Agent equivalent or execute sequentially when delegation is unavailable.

Run `node commander/status-line.js` only for requested session status or a `/ccc` menu flow that needs it. Menu rendering is separate from unsolicited session output.

## Execution and delegation

Carry the authorized task through implementation, validation, and a concrete handoff. Delegate bounded independent work when parallelism or specialist review materially helps. Give each worker ownership, constraints, acceptance criteria, and the required evidence; touching multiple files alone is not a delegation trigger. Keep small or tightly dependent work in the current thread.

`/ccc-orchestrate` writes a goal file for a Codex or Sonnet executor, then verifies its acceptance criteria. `/ccc-plan-exec` stays within Claude; `/ccc-handoff` preserves state before context becomes unreliable. Read their specific skill or `CLAUDE.md.template` only when that workflow applies. Write a durable handoff for a long task before compaction, preserving decisions, completed work, failures, and next steps.

Use the required isolated worktree for writes, stage only owned files, and preserve unrelated changes. A dirty main checkout is a baseline to protect, not a reason to reset other work. Publishing, deployment, tracker updates, messages, credential changes, and destructive actions require authorization for the actual action.

## Product architecture

- Desktop workflows are skills in `commander/cowork-plugin/skills/`, exposed as `/ccc-*`. Do not casually convert them to plugin commands or introduce namespaced UX.
- Active menus use AskUserQuestion-native pickers. Menu definitions are in `commander/cowork-plugin/menus/`; artifact templates remain in `lib/` for a future surface and are not the current menu renderer.
- `commander/cowork-plugin/agents/`, `hooks/`, `rules/`, and `.mcp.json` hold plugin capabilities and contracts. Connectors beyond the credential-free bundle are opt-in; tool references do not establish account access.
- `commander/cowork-plugin-codex/` is generated by `scripts/build-codex.js` from the Claude plugin and `commander/adapters/codex/`. Edit canonical source and validate the exact generated result; do not hand-patch only the generated distribution.
- CLI: `commander/engine.js`, `tui.js`, `dispatcher.js`, `knowledge.js`, and `plugins.js`. CLI state is under `~/.claude/commander/`.
- `skills/ccc-*/` are domain routers; load a matching router instead of the whole skill catalog. `commands/`, `prompts/`, `templates/`, and `compatibility/` supply the other toolkit surfaces.
- Keep personal overlays separate from the public installer. Historical documentation names `kevin/`, but that directory is not present in this checkout; do not assume it is installed. Public workflows must not depend on personal paths, credentials, or services.
- `claude-mem` remains external opt-in, not a bundled vendor: its AGPL license must not be silently folded into the MIT distribution.

Do not run the installer, updater, release script, or deployment as a documentation check.

Define observable success before substantial work. Inspect actual output and relevant errors. Stop once appropriate checks pass unless new evidence or unresolved risk warrants another pass. Report what changed, what was verified, and practical limits; do not claim a runtime fix from Markdown changes alone.
